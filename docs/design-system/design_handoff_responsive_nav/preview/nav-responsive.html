Responsive navigation

Top-nav and admin menu rebuilt around container queries so they react to their own container, not the viewport. Drop more menu items in — the layout collapses gracefully through three stages before falling back to a drawer. Admin menu trades its mobile horizontal-scroll for a native <details> dropdown (no JS).

3 · What changes in code

Three small, additive changes. No new files — only one CSS block appended, one PHP markup tweak, and the admin tab template rewrapped. Existing classes are kept so other styles still apply.

style.css · append at end of header block
/* === Responsive header (container-query based) === */
.header { container-type: inline-size; container-name: header-vp; }
.header-content { min-width: 0; }
.logo { min-width: 0; flex: 0 1 auto; }
.logo-text {
  font-size: clamp(0.95rem, 1.5cqi + 0.6rem, 1.25rem);
  white-space: nowrap; overflow: hidden;
  text-overflow: ellipsis; min-width: 0;
}
.nav { flex: 1 1 auto; justify-content: center; min-width: 0; }

/* Stage B: icon-only nav, year hidden */
@container header-vp (max-width: 1024px) {
  .logo-year { display: none; }
  .nav-link span { display: none; }
  .nav-link { padding: .5rem; width: 40px; height: 40px; }
  .user-name { display: none; }
}

/* Stage D: hamburger drawer */
@container header-vp (max-width: 560px) {
  .mobile-menu-btn { display: inline-flex; }
  .nav {
    position: absolute; top: 100%; right: 0;
    flex-direction: column; display: none;
    background: var(--bg-card); border-radius: 12px;
    padding: .5rem; min-width: 220px;
  }
  .header-content { position: relative; }
  .nav.active { display: flex; }
  .nav-link span { display: inline; }
  .nav-link { width: 100%; height: auto; }
}

Why container queries instead of media queries · the live .header width depends on .container max-width (1200px) plus padding — viewport width and header width drift apart on tablets, in PWA splits, in browser dev-tools sidebars, and once you start nesting layouts. Container queries fix it to the only number that matters: how wide the header actually is. Browser support: Chrome/Edge 105, Safari 16, Firefox 110 — all shipped 2022.
Adding new menu items in future · just append a <a class="nav-link"> — Stage A wraps to a new row if needed, Stage B already collapses to icons (5+ items fit in icon mode all the way down to 600px wide), Stage D drawer is a vertical list so unlimited items work. Same for admin: append a <a class="tab"> and a matching <a> in the dropdown menu.
